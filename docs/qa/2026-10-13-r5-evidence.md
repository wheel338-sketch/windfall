## `inst-fl-keys`

Changed files:

- `crates/windfall-dsp/tests/dsp/instrument_deadlines.rs` (existing registered DSP integration module).

The deadline gate constructs `AnyInstrument::PianoKeys`, prepares the actual
saved acoustic recipe's thirty generated key/layer sources off audio, then
guards reset, note admission/retrigger, parameter writes, mixing and release
against allocations/reallocations/frees. It does not substitute SamplePlayer,
a sine oscillator, a single-key bank or identical voices.

Release admission is explicitly **0.05 audio-duration share at 16 voices** and
**0.20 at the full 128-voice limit**, respectively 5% and 20% of one logical
core. Both are well below the general 0.75 gate, which is unchanged. Following
the existing `e1_cpu` convention, debug runs have a separately labelled 40x
diagnostic allowance. A debug pass cannot establish the low-CPU claim; release
logs identify `profile=release-admission`, actual ratio and release budget.

Twenty-four scenarios cover 44.1/48/96 kHz, 16/128 voices, fixed 64/256/480-frame
callbacks and repeating 1/7/64/127/511-frame callbacks. Every voice has a distinct
key, float velocity and pan; the velocity permutation selects both bank layers.
All voices must stay active throughout the 2-second held workload and subsequent
pedal-held interval. Strikes repeat before high notes exhaust their PCM; they
also exercise the existing fading replacement tails. Level, tune, release and
brightness change at absolute sample boundaries. Each scenario has three
identical trials and separate held/release/tail admission measurements, finite
nonzero held/release energy, bounded peaks, deterministic reset hashes, zero
allocator calls and exact final silence. Numerical observation is outside the
timed callback work. Slowest callback duration is logged as a diagnostic rather
than confused with an OS-scheduling-independent deadline assertion.

Sustain belongs to the real MIDI worker, which defers note-offs while CC64 is
down. The DSP timing profile renders that received lifecycle; the additional
worker test actually injects CC64-down, two differing key/velocity-layer strikes,
both key-ups and CC64-up through the existing fake *port* seam. The production
worker and PianoKeys engine must retain two audible voices after key-up, then
drain to silence on pedal-up with zero callback allocator calls.

The native Session test adds the real PianoKeys kind through checked commands,
sequences two keys at soft/hard velocities, compares nonzero live PCM to offline
PCM after the public reported latency, checks 7/64-frame partition equality,
changes to the electric recipe with undo/redo, saves/reopens, asserts the kind
remains PianoKeys and compares reopened live/export PCM with the electric bank.
No renderer/sound change or tolerance relaxation was made: edit-only work cannot
determine whether optimization is required. If release admission fails, repair
the renderer and rerun the existing reference tests; do not widen these budgets.

Fixed a concrete Stop gap: native Stop returns the tick to the playback start,
which may still be inside a placement. Raw AVI painting formerly ignored
`mediaClock.playing` and left/repainted a picture there. It now clears the actual
canvas while stopped and repaints on resume. The HTML picture is hidden while
stopped/outside the placement, with follower pause and the existing muted media
element preserved. Native soundtrack ownership remains exclusive. The raw
canvas records the frame index, source seconds, tick, epoch and output cursor
used by that drawing callback; the window test reads those together with actual
`getImageData`, never a later unrelated IPC frame.

The Windows script follows the analyzer/sample/notebook native-window pattern:
isolated configuration/WebView profile, occupied-port refusal, bounded CDP
connection/polling, prebuilt bundled debug executable, hidden process, report
and failure logs, and cleanup. It authors an original 4x2, 10 fps, 80-frame
bottom-up BGR24 + stereo 48 kHz PCM AVI, including RIFF stream formats and index.
Each frame encodes its identity in every pixel; each frame's PCM has different
nonzero left/right amplitudes. The native debug-gated `prepareVideo` operation
places that file **unmuted**, saves/reopens it through Session, and enters song
mode at 120 BPM. No tone/audio clip is added; all measured audio comes from AVI.
The existing smoke host mounts the **real VideoPlayer** against the saved
placement. Both native debug/explicit-config gates remain in force; no new IPC
command/DTO or production startup behavior is introduced.

The script asserts every RGBA pixel and exact frame/time correspondence to the
native painting clock at start, 0.75-second clip offset, seek to tick 1920,
native region loop `[960,1920)`, Stop and resume. It requires an actual observed
backward picture/tick wrap with an advancing native output cursor. Stop must
clear every pixel, empty source time and produce native soundtrack silence.
Start/offset/seek/loop/resume each record and require the live native mixer
analyzer's nonempty/nonzero stereo levels together with a playing picture.
The low but nonzero output gain is 0.01; silent app mode is explicitly disabled.
Missing decoder, output device, picture, native clock or bridge fails the run.

The portable native Session test independently authors raw RGB/PCM AVI bytes,
checks prepared picture bytes and 384,000 decoded soundtrack frames, drives the
actual Processor and Session realtime wire publication, and compares interior
stereo PCM with authored source sample values at start, offset, seek and loop.
Only the existing seek/loop fade margins are excluded; PCM tolerance is 1e-6.
It verifies clock tick/mode/epoch/output-cursor results, Stop silence and
save/reopen of unmuted placement and prepared bytes.

The mounted test uses independently authored AVI bytes and the real decoder
and VideoPlayer to assert submitted ImageData, source times and stop/resume
behavior. Its canvas is explicitly a **recording adapter**, not raster evidence.
`apps/desktop/package.json` has jsdom and no real Canvas implementation; the
brief disallows new dependencies. Real canvas implementation/readback is
therefore tested in the mounted WebView smoke host. A second mounted regression
checks HTML visibility, pause, muted audio ownership and Blob URL cleanup; it
does not claim a browser codec or native soundtrack test.
