## Rows

### `win-event-editor` — still partial (was todo); closest to complete

Implemented:

- Model: `Pattern.events`, a list of `PatternEventLane { id, target, points }`
  in pattern ticks, one lane per target, at most 64 per pattern, never the
  tempo. Omitted from JSON when empty; old files load without it.
  `crates/windfall-project/src/pattern_events.rs`.
- Commands: `SetPatternEvents` (captured `expected`, clamps, one undo step,
  a drag with a gesture id is one step) and `GeneratePatternEventLfo`.
- Lifetime: lanes go when their channel, track, effect or send goes and
  return on undo; they follow an effect to another track; duplicated and
  made-unique patterns get lanes with fresh ids. File validation refuses
  shared ids, the tempo, missing targets, duplicate targets and bad points.
- Engine: lanes compile into the existing automation lanes. In song mode
  every clip of the pattern plays its lane around from the clip's offset and
  ranks against automation clips by playlist row; in pattern mode the
  selected pattern's lane is followed around each pass. No allocation on
  the callback. `automation.rs`, `plan.rs`, `processor.rs`, `sequencer.rs`.
- UI: `apps/desktop/src/features/event-editor/` — window with pattern and
  control pickers, a curve with draggable, keyboard-movable points, point
  fields, clear, "Write LFO…"; "Edit events in pattern" in every
  automatable control's menu; `view.event-editor` action.
