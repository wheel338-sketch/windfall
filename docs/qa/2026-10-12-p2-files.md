## File backend and score foundation

All nineteen first-wave native file commands now have typed Backend methods and Tauri callers. Native presets and portable templates report an explicit desktop requirement in the mock; they do not fabricate disk/audio/native state. Plugin database built-ins and annotations use the actual Rust database through a new simulator operation. Scores use the actual Rust capture/load/reader/MIDI writer through the simulator, with a browser memory library.

MIDI files retain the entire expressive score in a standard marker, alongside interoperable ordinary notes; modified ordinary notes refuse stale metadata. Other MIDI applications may ignore the extension (reported on export).

## Managed extraction reclamation

Successful replacement now prunes unused own-session archive/template roots. It keeps current sample roots, current/history sample references, project-file roots and roots pinned by preset capture; returned IPC captures have no release handle and can be reused after replacement, so pinning is deliberately conservative. Only direct registered `projects/project-*` directories are removed, off document/audio guards. Untracked prior-session/user directories are never swept. Save/backup copying serializes with collection; archive jobs retain their existing single-owner guard.

Tests written, not executed: `extracted_template_audio_is_reclaimed_only_after_replacement_and_captures_pin_it`, plus direct guarded template races above. A capture-pinned root survives for the session lifetime; cross-session or abandoned-capture reclamation needs a durable lease protocol and is intentionally not attempted by this collector.
