## Delivered mechanism and files

`crates/windfall-dsp/src/rack_note.rs` exposes every scalar/table/chord/grid
control of all six note modules through append-only parameter descriptors and
Copy-only, finite, atomic setters. Descriptor counts are color 16, envelope 6,
scaler 5, splitter 8, mapper 133 and sequencer 53. The descriptor generator
source (`crates/windfall-dsp/examples/descriptors.rs`) adds `noteModules` with
paths relative to module JSON. Existing effect/instrument registry and parameter
orders are unchanged.

`crates/windfall-project/src/rack.rs` adds a serde-defaulted root
`RackGraph.parameters: Vec<RackParameterAddress>`. Each address stores the full
nested node path, module kind and stable descriptor index. Existing
`InstrumentParam` indices 0..31 stay macros; 32+n addresses registry entry n.
`src/automation.rs` resolves ranges/stored values. `src/lower.rs` preserves the
old registry prefix, appends new addresses, retains nested nextId high-water
marks, checks ordinary SetInstrumentParam commands and prunes deleted owners'
automation clips, pattern events and links in the same undo step. Deletions
leave address tombstones. Old built-in instrument lanes cannot be reassigned
to new note addresses. No Command or AutomationTarget enum variant was added.
Registry history is capped at 16,384 entries with a visible checked refusal.

`crates/windfall-engine/src/modular.rs` resolves the saved registry to flat
node/parameter pairs while preparing. Existing automation and internal-source
links apply these setters on the common 64-frame grid. `src/automation.rs`
restores the rack's stored values when a lane/link releases its target.
`src/rack.rs` updates the two admitted-note literals for the fixed shape stack.
Color/key/velocity/envelope controls are sampled when notes are admitted; mapped
keys and per-note envelope snapshots retain their accepted release ownership.
Live property-expression replay reads current scaler controls. Held sequencers
receive new controls without resetting phase or the ends of existing gates.
Playback and offline rendering share this implementation.

Notes retain up to eight independent envelope shapes. Gains multiply;
pan/pitch/X/Y contributions add, with final range clamping. Each release starts
from its own current level and decays over its own duration. Voice ownership
ends after the longest release. Admission rejects a ninth shape before
publication.

Aggregate admission counts flattened transit work and root starts, including
nested boundary Cartesian products. Every chord is charged its automatable
maximum of four voices. Checked limits are 256 transit events, 64 generator
seats per trigger and 1024 flattened wires. Mutually exclusive route outputs
are conservatively charged together. Concurrent note/voice exhaustion continues
through the existing bounded realtime refusal counters.

Auxiliary effect audio ports begin at 32 in EffectKind::aux_outputs() order.
Project checks reject unadvertised ports; engine routing uses
EffectSlot::process_routed, fixed frame scratch and existing compensation rings.
Muted processors clear every auxiliary port. The editor exposes the advertised
output names through `apps/desktop/src/features/modular/model.ts`.

Frontend changes:

- `features/modular/parameters.ts` reads generated Rust descriptors and resolves saved addresses; `lib/automation/targets.ts` resolves their UI ranges/values.
- `features/modular/editor.tsx` retains purpose-built note editors and adds an "Automation and controller links" panel using existing parameter gestures, automation/event menus and controller-link menus.
- `features/modular/library.tsx` uses the **already integrated** Backend preset capture/read/write/library facade. Files use native `.wfpreset` containers. Save captures the channel and complete root graph; rack load extracts only the rack and submits one checked graph edit. Generation/revision guards refuse stale reads. File/library loads allocate fresh root identities to prevent accidental inheritance of destination automation. Capability errors are displayed.
- `features/modular/examples.ts` defines original CC0-1.0 Soft double envelope, Two octave chord and Quarter beat pulse racks. They use Windfall processors and the selected instrument, with no third-party sounds/presets/art. Users can save them as normal rack preset files.

The seam contract is updated in `docs/integration/seams/modular-rack.md`.
No script-node variant exists in RackProcessor/RackNoteModule in this base;
the scripting worker's engine/runtime was not implemented or replaced here.
