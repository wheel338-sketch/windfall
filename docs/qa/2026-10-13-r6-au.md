## `wf-ui-scaling` — Audio Unit editor part

`crates/windfall-plugin-host/src/au/cocoa.rs` now embeds the retained factory
view as a child of the existing owned Cocoa `Window` parent used by CLAP.
It no longer refuses non-1.0 wrapper zoom. The NSView parent applies the
application-only bounds transform; AU frame sizes and EditorInfo stay in logical
AppKit points. Saved wrapper zoom is the base factor; live application zoom
multiplies it once, so the desktop's immediate global 100% update preserves a
saved 150% wrapper. AppKit applies backing density separately, including Retina
monitor changes. No plugin scale capability is fabricated or called.

`gui/au_geometry.rs` contains the portable size/zoom/monitor/close policy.
The thin Cocoa integration polls native view-frame requests and parent bounds,
admits plugin/user resizing, rejects invalid sizes without changing accepted
geometry, reapplies the point transform on monitor transitions and supplies
resize notifications. Live zoom admits pending resize/close first. The shared
Window delegate defers the close button until owner teardown. Declared field
drop order detaches/releases the retained AU view/factory/bundle before the
host parent and its delegate/class retire. Attached Tauri owner, title, focus
and placement are passed through the shared Window.

`au/mod.rs` implements `InstanceBackend::set_editor_scale`, polls that geometry
from owner-side idle and emits `EditorResized`/`EditorClosed`. All native objects
and calls remain behind macOS cfg and on the existing Cocoa-main owner.
The portable model is registered for tests on Windows through `gui/mod.rs`.
