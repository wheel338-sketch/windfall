## `core-lifetime-free-updates`

Changed `src-tauri/src/{updates,update_transfer,lib,window_calls}.rs`,
`session/{update_shutdown,mod,files,recording,preparation,audio,transport}.rs`,
`plugins/runtime.rs`, desktop Cargo/config and
`src/features/updates/{native,section,section.test}.tsx/ts` plus the caller-aware
backend adapter. New Rust test modules are registered.

Source implemented:

- An owned session freeze is acquired before returning the native snapshot used
  by the unsaved-work prompt. It joins saves and refuses document publication,
  controller edits, native state updates, prepared background edits, replacement,
  recording admission and new audio configuration. Ordinary IPC exclusion alone
  is not relied on. The UI presents Save and install / Discard and install /
  Cancel, with a save-path dialog when needed; missing native decisions refuse.
- Installation stops input monitoring, acknowledges output callback/stream
  destruction on the device owner, then joins the hosted-owner retirement FIFO.
  Automatic device recovery is canceled. RAII cancellation/error paths thaw
  admission, reopen audio and restore monitoring, reporting reopen failures.
  Native main-window destruction releases a pending prompt's freeze. Installer
  refusal preserves the verified candidate for retry. The Tauri before-exit hook
  preserves live windows when Windows ShellExecute/UAC refuses to start.
- External manifests are limited to 1 MiB and packages to 512 MiB. HTTPS and
  credential-free redirects, a three-redirect limit, connect/total timeouts,
  declared-length rejection and streamed chunk accounting precede accumulation.
  A chunk crossing the remaining budget is refused before reserve/extend.
- Bounded bytes are replayed over a random, one-shot 127.0.0.1 capability URL to
  the actual Tauri `Update::download` Minisign verifier. Production download and
  the generated-key test call the same `verify_bounded_bytes` function. The test
  signs a package and asserts exact accepted bytes and corrupt/truncated/wrong-key
  rejection. Redirect-loop tests use the production credential/count validator,
  normalizing only the local fixture's scheme; HTTPS refusal is separately tested.

The Tauri config's `dangerousInsecureTransportProtocol` is enabled solely for
bounded local replay. The external HTTP client still refuses HTTP/credentials;
the frontend has no direct updater-plugin permission. Replay disables proxies
and redirects and uses connection/read/write/deadline limits. Integrator must
review this trust boundary; peak package memory can approach twice the cap while
Tauri copies the bounded replay into its verifier buffer.

Source implemented: every remaining built-in family receives per-voice note pan
before summation, with retained project law and a five-millisecond frame-clock
linear gain ramp. Gains/trigonometry and ramp steps are computed at note/control
events; each sounding frame uses cached arithmetic, with no new allocation,
lock, IO or per-sample trigonometry/division in the shared ramp. Analog output
saturation remains after stereo summation. Registry dispatch and both test
tables are exhaustive, so adding an instrument kind requires an explicit case.
No existing CPU deadline or tolerance was changed.

fixed atomics rather than advertising MIDI emulation as native support. The
in-process desktop host caches and ramps per-note gains and only applies its
Pan/Volume compensation when all required native capabilities exist. Direct
host clients which do not opt into a project law retain native expression
semantics; the engine explicitly supplies its project law. The settings UI
shows capabilities/refusals, refreshes them with revision/generation guards and
keeps unsupported operations from masquerading as success.
