## What changed

- `crates/windfall-engine/src/export_positions.rs`: new `RenderFrameMap` stores
  sequencer clocks actually used by the offline pass. Linked clocks use musical
  ticks directly; the static case retains the compiled warp from the same plan.
  It does not reconstruct linked tempo from stored BPM, controller settings or
  static automation. Frame lookup uses the sequencer's exact frame rounding.
  Unchanged clocks are compressed; capture allocates only after processing has
  returned, on the offline caller. Tail processing is excluded from the musical
  tempo proof. Range bounds and missing capture return explicit errors.
- `engine/src/{processor,sequencer,lib}.rs`: copy-only clock accessor, clock
  equality and public render-map export. No callback storage, allocation, free,
  lock, wait or IO was added.
- `engine/src/stems.rs`: streaming results carry their render map. Track-output
  stems use their shared processor; To-master stems return the authoritative
  full-mix map and retain the existing effective-tempo replay. Linked processing
  already splits at the 64-frame control grid; metadata captures those clocks.
  Static processing retains its existing block/progress behavior.
- `engine/src/stems/playlist.rs`: isolated playlist stems now also capture and
  replay the full mix's effective tempo, even when no mix file was requested.
  Removing a detector-input lane cannot change the stem's clock. These results
  return the full-mix map and measured duration.
- `engine/src/tempo.rs`: checks constancy over the selected musical range for
  an ordinary compiled tempo lane, including constant ranges of an automated
  song. Linked constancy is checked from captured clock slopes instead.
- `crates/windfall-codec/src/{wav,encoder}.rs`: bounded rendered-metadata setters
  append standard RIFF chunks after `data`, without buffering or moving PCM.
  Validation uses the measured PCM frame count; trailing chunks participate in
  RIFF size and maximum-file-size accounting. Invalid metadata and conflicting
  pre-render metadata are refused before publication. Existing staged-file
  finalization and destination rollback remain in force.
- `apps/desktop/src-tauri/src/session/export_markers.rs`: song cues, navigation
  end frames, loop endpoints and pattern markers/note cues use the render map.
  Pattern note `ltxt` regions map both musical endpoints to actual frames,
  including swing, shift and gate. Repeated cue origins and beat extent use the
  prepared render pass length. Region frames use their actual seek epoch; they
  are not estimated by subtracting two stored-tempo positions.
- `session/export.rs`: opens encoders without guessed markers, renders audio,
  then derives and installs metadata before staged finalization, including full,
  region, mixer and playlist stem export paths. Mastering still preserves frame
  coordinates and installs the metadata after its final PCM is written.
- `crates/windfall-ipc/src/lib.rs`: default-compatible optional
  `ExportProgress.wav_metadata` (`wavMetadata` on the wire). Successful WAV
  results explicitly report whether constant tempo/beat metadata was written
  or omitted. No static ACID or `WindfallBeats/1` claim is emitted for a changing
  linked clock. Existing meter representability restrictions also apply.
- `docs/audio/wav-interchange.md`: documents actual-clock positions, region
  epochs, stem replay, note regions, tempo omission/reporting and trailing RIFF
  chunks. Source-frame editor/slice attributes continue to use their existing
  source/view coordinate transforms; those standalone source exports do not run
  a song controller clock.

No new dependencies. No persisted registry or descriptor order changed. The
only additive wire field needs normal integrator binding regeneration; generated
bindings and WASM/simulator artifacts were not edited.
