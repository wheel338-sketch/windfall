### Group D — both large-delay rows

Production:
`crates/windfall-engine/src/effect_host.rs`,
`plan.rs`, `project_preparation.rs`, `rack.rs`, `state.rs`,
and `docs/DELAY-FAMILY.md`.

One shared pool follows the controller's plans/attachments. Admission charges
all new payload before replacement effect construction, including queued and
speculative candidates. Reservations move with concrete EffectUnit owners,
including fading and retiring owners, and release only after their slot storage
is freed on the control side. The last EffectUnit field holds the token so
field Drop order cannot release it before history destruction. Metadata clones
do not double-charge an owner. Old-rate history remains charged before the
old ledger is filtered for reuse. Leaving plan definitions also count in the
existing per-plan size check.

Retained echo-payload limit: 1 GiB. Shared peak limit: 1 GiB +64 KiB staging.
Other concurrent staging is conservatively charged as occupied memory.
Zero-new-payload reuse proceeds without reserving more memory. Failure/cancel
returns candidate payload/staging; refusal preserves the installed plan/PCM.
This bounds one controller's echo payload, not every host allocation or every
independent offline renderer. No pool operation is added to process, reset or
parameter changes; callback adoption only moves existing units.
