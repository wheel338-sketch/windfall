## fmt-wavpack

Changed files:

- `crates/windfall-codec/src/wavpack.rs`: independent Rust lossless integer
  codec. Encoder supports mono/stereo 16/24-bit PCM, rates 1..16777215 Hz,
  caller-selected 1..65536-frame blocks, 32-byte version-4 headers, known total
  samples patched into every audio block, frame indices, flags, PCM CRC,
  decorrelation terms/weights/history, adaptive median Golomb bitstream and
  entropy metadata. It uses a term-1, delta-2 predictor. RIFF wrapper sizes are
  patched; odd PCM has a RIFF trailer pad. Bounded APEv2 title/artist/genre/comment
  tags are emitted. AtomicFile staging protects the existing destination.
- Decoder implements 1..8, 17, 18 and -1..-3 predictor terms, multiple passes in
  reverse decode order, initial weights and logarithmic history, joint stereo,
  false stereo, median adaptation, held unary prefixes, extended unary codes,
  Elias zero runs, adjusted-binary remainder coding, integer zero/one/duplicate
  restoration, header shifts, PCM CRC and version-5 block checksums. Metadata-only
  trailing blocks are validated without changing stream layout. Header, block,
  metadata, decoded-memory, unary and block-count budgets return errors.
- `crates/windfall-codec/src/{lib,decode,encoder}.rs`: append-only format
  registration, `.wv` extension, magic detection, file/byte ordinary and strict
  decode, probe, common streaming encoder API.
- `apps/desktop/src-tauri/src/session/audio_editor.rs`, `commands.rs`,
  `apps/desktop/src/lib/ipc/{backend,tauri,mock}.ts`,
  `apps/desktop/src/features/audio-editor/index.tsx`: save the selected rendered
  editor view as 16/24-bit WavPack. It preserves the document/history; its token,
  source allocation, generation and edit guards are checked before publication.
  Encoding is outside the document lock; only the final guarded rename holds it.
  A refused output removes its staging file. Save-dialog cancellation does not
  invoke encoding. Browser mode reports its native capability error.
- `crates/windfall-ipc/src/lib.rs`, native `session/export.rs`, frontend
  `features/export/{format-controls,names}.ts*`: append `.wv` export, integer
  depth choices and filename handling. Normal sample import/browser preview
  reuse the codec decoder; picker extensions include `.wv`.

Mandatory behavior implemented in source: lossless 16/24-bit mono/stereo encoding
and decoding, bounded hostile input handling, editor save, native export and
sample import/preview/reopen. Floating-point and >24-bit integer WavPack,
hybrid/correction/lossy, DSD, multichannel sequences and 40-bit file indices are
clearly refused. Float was optional in the brief and has not been implemented.
The encoder quantizes finite f32 once without dither; integer-quantized input is
preserved bit for bit. This does not promise lossless preservation of arbitrary
unquantized editor float values beyond the chosen integer depth.

## fmt-export-m4a

Changed files:

- `crates/windfall-codec/src/aac.rs`, `aac/mf.rs`: Windows Media Foundation's
  synchronous AAC-LC encoder, with COM/MF startup/shutdown RAII and thread
  affinity. Negotiates PCM16 mono/stereo at 44.1/48 kHz, 96/128/160/192 kbps,
  feeds complete finite PCM frames with nonzero timestamps/durations, reads the
  encoder-supplied AudioSpecificConfig, drains raw AAC access units and forwards
  them to the existing muxer. MFT not-accepting/need-more-input/decoder stream
  changes and COM output ownership are handled with bounded loops/buffers.
- The OS encoder does not document a stable priming count. A separate bounded
  8192-frame original calibration signal is encoded then decoded with the OS
  decoder, and normalized correlation measures its lag within 0..4096 frames.
  An uncertain calibration produces a capability error. The real encoder is a
  new transform, so calibration does not enter the exported audio. Final flush
  includes four 1024-frame zero blocks to preserve its last analysis window; exact input
  length plus measured delay determines padding for the gapless edit list.
- `crates/windfall-codec/src/{m4a,mp4,encoder,lib}.rs`: muxer consumes validated
  encoder-supplied ASC, normal Encoder writes M4A, and a checked repository MP4
  parser reads sample entry, descriptors, timing/chunk/size/offset tables, track
  duration and edit list. `decode_m4a_bytes` independently decodes the parsed raw
  AAC packets through the installed OS decoder and honors trim. That function
  is an acceptance helper/API; general `.m4a` sample import is not advertised.
- Native `session/export.rs`, `commands.rs`, IPC `lib.rs`, frontend backend/
  tauri/mock, `features/export/{format-controls,names}.ts*`: actual rendered
  song/pattern export, bitrate choice, default-compatible optional `aacBitrate`,
  `.m4a` path/dialog, native capability probing and an unavailable reason beside
  the disabled M4A option. Unavailable platforms/configurations and browser mode
  return errors; there is no simulated codec success. Existing native multi-file
  staging transaction surrounds codec finalization and checks cancellation
  before publication. Existing project title/author/genre/comments reach M4A.

Mandatory behavior implemented in source: OS AAC encode, muxing, priming/padding,
tags, bitrate, cancellation/error destination preservation and native/IPC/UI
song export. Windows is the supported encoder platform; other platforms show
the required explicit capability error. No other OS encoder is bundled or
advertised. The independent decoder is the OS AAC transform, not our encoder.

Dependency/features: `windows` **0.62.2**, already present in Cargo.lock, added
to codec's Windows-only manifest dependencies (MIT OR Apache-2.0). Features:
`Win32_Foundation`, `Win32_System_Com`, `Win32_Media_MediaFoundation`.
Cargo.lock only gains `"windows"` in windfall-codec's dependency list; no package
version/checksum change, encoder library or other dependency was added.
