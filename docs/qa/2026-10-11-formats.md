## WAV markers, loops, slices and tempo

`wav_metadata.rs` adds frame-based `WavMetadata`, validated cue IDs, UTF-8 labels,
`cue ` + `LIST/adtl/labl`, `ltxt` slice regions, `smpl` loops/unity note and `acid`
constant-tempo/meter fields. API loop ends are exclusive; disk ends are inclusive.
Counts cap at 4096, labels at 1024 bytes, total metadata at 4 MiB. Reader seeks
past audio/unknown chunks and checks RIFF/chunk boundaries before allocation.
Unsupported fractional loop/tuning and malformed metadata return errors.
`WavWriter::create_with_metadata` and `Encoder::open_with_wav_metadata` preserve
existing atomic publication; finalization checks positions against actual frames.
Non-WAV encoders refuse nonempty WAV metadata.

Desktop WAV song export captures project timeline markers from the immutable
render snapshot. `SongFrameMap` uses the same compiled tempo map and absolute
endpoint rounding as audio export. Selected regions rebase positions; loops
must be wholly inside the region. ACID is emitted only for constant tempo/meter
and integral quarter-note duration. Tails are outside the declared musical body.
Skip/pause navigation is refused with an actionable error until physical output
position mapping exists. Loop navigation is disabled by existing export behavior.
Mixer/playlist stems share the song clock. Pattern-mode export currently has no
marker metadata. Slice arrays have codec coverage but are not wired to SliceMap /
SliceDeck workflows or generic audio import.

Public layouts: [Microsoft RIFF documentation](https://www-mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/RIFFNEW.pdf),
[WAVE overview](https://www-mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/WAVE.html),
[libsndfile wav.c ACID layout](https://github.com/libsndfile/libsndfile/blob/master/src/wav.c).
No additional dependency or copied source was introduced.

## WavPack decision

Inspected `Cargo.lock` and codec dependencies: no WavPack/pure-Rust implementation
is already present; enabled Symphonia codecs exclude WavPack. `.wv` is not in
`AUDIO_EXTENSIONS`, no encode/decode entry point exists, and no new decoder or
extension claim was added. Existing formats are unaffected.

[WavPack 5 public format document](https://www.wavpack.com/WavPack5FileFormat.pdf)
describes the block/metadata framing. The implementation requires much more:
metadata-dependent decorrelation, entropy medians/adaptation, joint-stereo and
channel interleave, integer/float extensions, hybrid correction pairing,
checksum/CRC, version flags and hostile-input budgets. Implementing only headers
or one self-generated entropy case would not meet the task's audio correctness
standard. A correct independently implemented decoder was not achievable within
this stream; there is no pretend decoder or test evidence.

The [official implementation](https://github.com/dbry/WavPack) carries a
[BSD-3-Clause-style license](https://github.com/dbry/WavPack/blob/master/license.txt),
a candidate compatible with this project's GPL distribution after a concrete
revision/build/dependency/license review. **Recommended user decision:** permit a
separate reviewed dependency proposal for vendored official C code and bounded
Rust bindings, rather than ship an unverified new decoder. Alternatively retain
an independent pure-Rust implementation as a separate funded scope. No package
was added casually; encode remains open too. Neither option is selected here.
Acceptance must include independently encoded small mono/stereo 16/24/32-bit and
float files, corrupt CRC, multiple blocks, invalid metadata, hybrid/correction
policy, frame budgets and independent decoded PCM checks; round-trips solely
through a home-written encoder do not establish correctness.

## M4A container and encoder decision

`m4a.rs` implements an atomic AAC-LC muxer: `ftyp`, `mdat`, `moov`, audio sample
entry, AAC AudioSpecificConfig/ES descriptors, timing/chunk/size/offset tables,
gapless edit list and UTF-8 title/author/genre/comments. Bounded to 1,000,000 raw
1024-frame access units, 256 KiB per unit, 32-bit file/box offsets, mono/stereo
and supported AAC sample rates at most 64 kHz. ADTS framing is rejected. No
fast-start, HE-AAC/SBR/PS, encryption, variable frame length or high-rate sample
entry support. `AacEncoderAdapter` defines configuration, interleaved PCM encode,
packet emission, flush and delay/padding contract. Adapter owns syntax correctness,
input bounds and cancellation; muxer does not pretend to validate AAC payloads.

[FFmpeg movenc.c](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/movenc.c)
is public container layout evidence. Candidate encoder is FFmpeg's native AAC
encoder through a separately reviewed build/adaptor; see its
[codec documentation](https://ffmpeg.org/ffmpeg-codecs.html) and
[license documentation](https://ffmpeg.org/doxygen/trunk/md_LICENSE.html).
Do not enable incompatible/nonfree dependencies: FFmpeg specifically identifies
FDK-AAC as incompatible with GPL. OS Media Foundation / AudioToolbox are alternate
platform adapters with separate terms/availability; no promise of compatibility.
Open-source copyright terms do not decide patent obligations. **User decision:**
select supported platforms, encoder/build/distribution plan and jurisdictional
patent review, or keep M4A unavailable. No encoder dependency, IPC enum/menu option
or export success claim was added. The row must remain open until this decision,
real encoded-audio decoding tests and desktop persistence/error/cancel acceptance.

Tests **written, not executed**, `crates/windfall-codec/tests/m4a_mux.rs`:
`mux_tables_offsets_duration_trim_and_tags_match_independent_box_walker`,
`refusal_and_abandoned_mux_do_not_replace_existing_destination`. Payload bytes are
invented structural fixtures, **not valid AAC and not measured audio evidence**.

## ZGR and legacy presets

The [official ZGR manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_open_zgr.htm)
describes a slice grid mapped to sampler channels, but supplies no byte layout.
Targeted public parser/document searches did not locate a sufficient description.
No magic header, guessed offsets or generated invented-ZGR fixtures were added.
Keep open until an independently auditable format description is found; user can
choose an explicit scope deferral, but a deferral does not make parity done.

For `.ds`, [LMMS DrumSynth.cpp](https://github.com/LMMS/lmms/blob/master/src/core/DrumSynth.cpp)
contains a public GPL-2.0-or-later text parser and rendering behavior.
`DrumSynthPreset` retains bounded case-insensitive section/key/value fields,
including unknown entries. Caps: 64 KiB input, 2048 bytes/line, 64 sections,
512 fields, 32 envelope points, caller frame budget capped at 3,840,000.
Finite/ranged numbers, duplicate keys and monotonic envelopes are checked.
Offline conversion renders an explicitly approximate tone/flat-white-noise
subset with stretch, level, tuning, phase and linear envelope. Active overtones,
noise bands, distortion, filters, noise slope and tone droop are refused.
Unknown fields remain visible with warnings; source random sequence, integer
rounding and tail padding are not reproduced. No realtime allocation/IO path
or silent registration as ordinary audio was added. Desktop import/preview that
shows warnings and preserves preset fields is still required.
