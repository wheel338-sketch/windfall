## Row wf-multithreading — implementation ready; acceptance pending

The production engine now executes independent built-in instrument channels
and mixer effect/EQ/stereo chains on prepared plan-owned workers, with the
callback participating. The compiler builds consecutive independent stages
from the actual cycle-repaired routing order and every audio/send/sidechain/aux
edge. Keeping stages consecutive preserves the original summation order.
Instrument rendering is the source stage before channel reduction and mixer
stages; MIDI generators/routes run first on the callback as before.

Every rendered track has its own prepared scratch and existing output buffer.
Worker jobs borrow only disjoint DSP fields and read-only stage inputs; they
never borrow the whole Mixer/PlanState while another lane runs. Capacity-one
SPSC queues admit at most one job per worker. Workers spin briefly between
stages, then use the prototype's timed idle polling, so publication cannot lose
a wake and the callback uses no OS wake/wait, mutex, allocation or destruction.
Windows affinity setup and a readiness handshake finish before admission.
Threads are bound to the lifetime of the prepared PlanState.

All routing, faders, meters, disk taps and channel/bus accumulation retain
serial plan/edge order after the stage barrier. Existing sidechain, auxiliary
output and PDC delay semantics are retained. Current, routed-aux and hosted
tracks use singleton/callback processing; control-producing plans serialize
mixer processing because their shared controller runtime has ordered effects.
Hosted instruments, MIDI generators and Dashboard remain on the callback lane.
Shared sampler voice/cut/steal ownership also stays on the callback. Master and
track background logging (including the enabled-by-default master logger) keep
parallel effects active; a stage with a requested intermediate effect-slot log
uses the serial lane to preserve that capture and its single-producer queue.

Deadline policy is **completed output, late**. No timeout steals an unfinished
node or starts a second copy of it. Every completion is harvested before any
plan adoption, reset or retirement. Late nodes increment `processing_overruns`
and publish a typed track/channel identity in `Controller::stream_stats()`;
`xruns` increments once for the output buffer. The native converter propagates
one device-buffer deadline across its bounded stereo subblocks, and device CPU
measurement does not double-count the same deadline miss. A reduction-only
miss identifies master. Queue storage/probing is bounded; completion time is
intentionally allowed to exceed the deadline until the node finishes.

Workers and scratch retire inside the old PlanState, or a `Garbage::Workers`
carrier for a count-only change. Control-side retirement stops and joins them
before final destruction. Live count changes replace no DSP, notes, delay
histories, ramps or playhead. Automatic selects available cores capped at eight;
explicit values 1–8 are supported, including 1 = serial. Invalid counts and
worker-creation failures are reported. Application settings default legacy
files to automatic, persist explicit choices and restore them on startup.
Audio settings expose the preference; thread-only changes avoid reopening the
device, including during playback/recording. Refused changes restore the
backend's authoritative preference and display the returned capability error.

Desktop exports capture the resolved live count. Buffered, streaming and stem
renders use the same Processor/schedule through `RenderOptions::audio_threads`.
The standalone Rust render default remains one lane. Streaming/stem preparation
now returns a worker/attachment error instead of panicking on that failure.
