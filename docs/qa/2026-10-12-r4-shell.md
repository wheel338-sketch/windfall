## `wf-detached-windows`

Changed `src-tauri/src/{window_calls,commands,files_commands,lib,updates}.rs`,
`capabilities/default.json`, `src/lib/ipc/{tauri,backend}.ts`, its three native
adapter test files, and the existing sample-window smoke helper.

All 205 custom IPC definitions now take a transient `caller` with the server's
document generation and a random token for that native window opening. The
guard is the first statement, including presets, plugin insertion, preparation,
imports, recording, automation, assistant/script, transport and cleanup paths.
The two snapshot endpoints are the only exceptions and only read the document.
Generation is sampled under the invocation mutex, avoiding a replacement between
checking its mirror and admitting a call. Blocking preparation retains the
control-side lease through its final admission. Project-new/open/archive-open,
FLP-open, template-new and installation are exclusive against outstanding calls.
Other simultaneous prepared edits retain the existing session admission rules.

Close/dock retire the opening token; bootstrap cannot revive a closing window.
Close refuses outstanding work, native failure restores the still-live opening,
and docking requires a live main window and refuses a busy target. Native destroy
is behind the checked command; frontend core destroy permission is removed.
Close confirmation also captures its project epoch. Hosted Windows editors use
the calling window as their native owner. The smoke helper now carries caller
identity for raw custom IPC.

Written, non-ignored tests in registered `window_calls.rs::tests`:

- `every_custom_ipc_has_a_caller_lease_and_refuses_both_stale_identities`
- `replacement_waits_for_all_custom_calls_and_failed_calls_release_ownership`
- `reopened_label_cannot_reuse_a_departed_window_token`
- `accepted_close_revokes_queued_edits_and_waits_for_running_preparation`
- `docking_retires_the_target_opening_and_recovers_from_native_close_failure`

The first test recursively inventories command definitions, reconciles the
registered handler, checks each first guard and exercises every row against

## `wf-help-tutorials`

Changed desktop `events.rs`, `session/export.rs`, its registered `tests/export.rs`,
the export IPC/backend/simulator adapters, `features/export/{requests,export-dialog}`,
`features/help/{guided-tutorial,tutorials}`, recording store and their test files.

Export gets a bounded UUID correlation field in a transient event envelope,
outside musical/generated types. It survives the native worker's progress,
success, cancellation and error. The real form and guide match request ID,
path, guide owner and project generation; reusing a filename or receiving a
foreign window's completion cannot satisfy the guide. Retries within the same
form retain guide ownership; closing an unsubmitted form clears intent. A real
successful guide request remains completed across later focus/activity changes.

Recording focus/visibility return refreshes native state. Device loss or errors
offer reachable setup recovery; an active failed capture has an explicit
discard-and-retry action. An already kept clip can satisfy the recording-start
step even if active capture ended before Next. Cancelled/failed exports offer a
retry without satisfying completion. Listeners/intent are released on unmount.

Written tests:

- `features/export/requests.test.ts`: both correlation/terminal-state cases

- `guided-tutorial.test.tsx`: “explicitly discards an active failed capture before retrying device setup”
