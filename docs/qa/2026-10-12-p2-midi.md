## Capture seam (core-midi-support / wf-midi-recording)

Recorded notes submit the existing `AddNotesWithCurves` transaction. Static wheel state at key-down is fine pitch; CC74 is modulation X; CC1 and pressure share modulation Y (last event wins). Wheel range is ±200 cents. Movements match the input slot and zero-based MIDI channel, have held segments, and normalize against the unsnapped sounding duration. Snapping translates the note and its contour together. A pattern wrap crops at the first pass end. The piano worker owns display/editing of the saved `NoteExpression` and `Pattern.note_curves`; no new saved note model or command was introduced.

Native test: `session/tests/controllers.rs::wheel_pressure_and_cc_capture_attach_curves_to_native_note_ids_and_survive_history_and_file` — written, not executed. Tests source isolation, wheel/CC74/CC1/pressure, new native IDs, quantization, curve ownership, validation, undo/redo and JSON reopen.

Current risks: capture assumes the existing audition key ownership policy; same-key input collisions retain that policy. Publication binds its observed generation under the document lock; same-generation refusals retain a bounded take for retry.

## Audio-aligned scheduling

`core-midi-support`, `wf-midi-sync`: note deadlines use the DAC frame timestamp minus the output port's reported `latency_nanos`; DAC latency is already in `OutputClock.nanos` and is not counted twice. MIDI clock uses the audio-time position of the published playhead endpoint, not its delayed worker observation. A future DAC start is delayed until the compensated origin. The output seam defaults unknown device latency to zero; a synthetic port explicitly reports 3 ms.

`midi_hardware/routing_tests.rs::injected_audio_clock_and_port_measure_compensated_notes_and_clock_jitter` — **written, not executed**. Drives the real worker scheduler with injected monotonic/DAC clocks, irregular wake-ups and a timestamping port; independently pins note-on/off deadlines and 120-bpm clock pulse mean/RMS error bounds. Risk: first-run clock phase and existing clock regression tests should be checked first. Driver/surface latency calibration and OS jitter remain external.

## MIDI-out routing and native plugin admission

`core-midi-out`: MIDI-out params add hardware slot and hosted destination metadata; all 21 existing automatable descriptor indices are unchanged. Routing edits use exact integer IDs through `SetInstrumentParams`, avoiding float-valued destination IDs. Eight independently connected output slots share a worker; each uses its own reported latency and retains byte order. Disabled additional slots keep their indices. Project/plugin destinations are validated; destination removal disconnects sources (never falls back to hardware) in the same undo step. Removing a sounding MIDI source drains releases before retiring its fixed state, while transport continues. Prepared MIDI state adoption preserves old-route ownership. The dedicated editor exposes named hosted destinations and hardware slots; settings configure extra outputs.

Hosted MIDI is admitted before rendering, with one-frame subblocks when a plugin route exists. CLAP receives raw controller/program/wheel events; VST3 uses IMidiMapping queried off the callback and translates mapped controls into normalized parameter points. Unmapped VST3 controls refuse the block rather than silently disappearing. Native owner exchanges retain controller state for replay and channel/key notes for release. Bridge protocol is **v7**, with 16-channel recovery snapshots and raw channel-voice event kind 8; helper and desktop must be rebuilt together. No arbitrary native call was added to the engine callback.
