## MIDI-out routing and native plugin admission

`core-midi-out`: MIDI-out params append hardware slot and hosted destination selectors after descriptor index 20. Eight independently connected output slots share a worker; each uses its own reported latency and retains byte order. Disabled additional slots keep their indices. Project/plugin destinations are validated; destination removal disconnects sources (never falls back to hardware) in the same undo step. Removing a sounding MIDI source drains releases before retiring its fixed state, while transport continues. Prepared MIDI state adoption preserves old-route ownership. The dedicated editor exposes named hosted destinations and hardware slots; settings configure extra outputs.

Hosted MIDI is admitted before rendering, with one-frame subblocks when a plugin route exists. CLAP receives raw controller/program/wheel events; VST3 uses IMidiMapping queried off the callback and translates mapped controls into normalized parameter points. Unmapped VST3 controls refuse the block rather than silently disappearing. Native owner exchanges retain controller state for replay and channel/key notes for release. Bridge protocol is **v7**, with 16-channel recovery snapshots and raw channel-voice event kind 8; helper and desktop must be rebuilt together. No arbitrary native call was added to the engine callback.
