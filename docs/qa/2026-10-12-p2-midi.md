## Capture seam (core-midi-support / wf-midi-recording)

Recorded notes submit the existing `AddNotesWithCurves` transaction. Static wheel state at key-down is fine pitch; CC74 is modulation X; CC1 and pressure share modulation Y (last event wins). Wheel range is ±200 cents. Movements match the input slot and zero-based MIDI channel, have held segments, and normalize against the unsnapped sounding duration. Snapping translates the note and its contour together. A pattern wrap crops at the first pass end. The piano worker owns display/editing of the saved `NoteExpression` and `Pattern.note_curves`; no new saved note model or command was introduced.

Native test: `session/tests/controllers.rs::wheel_pressure_and_cc_capture_attach_curves_to_native_note_ids_and_survive_history_and_file` — written, not executed. Tests source isolation, wheel/CC74/CC1/pressure, new native IDs, quantization, curve ownership, validation, undo/redo and JSON reopen.

Current risks: capture assumes the existing audition key ownership policy; same-key input collisions retain that policy. Remaining work is tracked in later sections as this handoff is updated.

## Pattern automation / audible overdub / count-in

The whole recording pass, mouse/hardware edits and curve commit, shares one gesture ID. Existing curves retain data outside the overdub range. ## Audio-aligned scheduling

`core-midi-support`, `wf-midi-sync`: note deadlines use the DAC frame timestamp minus the output port's reported `latency_nanos`; DAC latency is already in `OutputClock.nanos` and is not counted twice. MIDI clock uses the audio-time position of the published playhead endpoint, not its delayed worker observation. A future DAC start is delayed until the compensated origin. The output seam defaults unknown device latency to zero; a synthetic port explicitly reports 3 ms.
