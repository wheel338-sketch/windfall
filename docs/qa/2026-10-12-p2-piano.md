# Second pass — piano roll and event editing

Branch `gpt/p2-piano`, base `038a7de0970be077857db15a32a54a2cb82b8f74`.
Implementation hand-off; every new test is **written, not executed**.
The worker brief prohibits builds, generators, tests and sub-agents.

## Seams

- MIDI capture owner supplies `Pattern.noteCurves` and note expression using
  the existing note/curve commands. Piano rendering/editing reads that canonical
  data; no parallel frontend capture model.
- `midi:note` must report accepted sounding down/up transitions, with deferred
  up for sustain and releases on panic/disconnection/destination replacement.
  Chord state keeps hardware ownership separate from audition ownership.
- Bridge worker owns helper-provider expression negotiation and recovery.
  This branch owns desktop native expression mapping and engine-facing transport.

## Native expression and phrase transport

Native desktop owners now resolve the saved seven-kind expression map at onset,
edits and owner-exchange replay. Removed destinations reset to neutral; saved
pitch includes the latest fractional/gliding value and color group. CLAP inputs
advertising MIDI-only notes use channel bend (declared map range), CC and pressure
fallback, including bend before onset, shared-key release ownership, restoration
of a remaining channel owner and panic neutralization. All storage is prepared;
groups fit fixed eight-event stack buffers. No bridge ABI/provider changes.

Bridge assumption: `gpt/w3-plugin-hosting` supplies equivalent cached negotiation,
instance onset/expression/release groups, current-map replay and MIDI fallback on
its provider path. Its merge and joined execution remain mandatory. VST3 native
per-note capability uses the existing cached negotiation; a VST3 input with only
legacy MIDI mapping still needs cached IMidiMapping fallback (not implemented here).

instance/channel releases, and measures MIDI bend. Authored, **not executed**:
