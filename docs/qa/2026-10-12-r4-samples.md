## Shared implementation for the six sample-bank instrument rows

Files: `crates/windfall-dsp/src/sample_bank/{budget,asset,mod,soundfont}.rs`, `crates/windfall-dsp/src/instrument.rs`, `crates/windfall-core/src/lib.rs`, `crates/windfall-engine/src/{pool,sample_instruments,rack,state,processor,message}.rs`, `apps/desktop/src-tauri/src/samples.rs`, and native `session/{preparation,files,samples,archive,sampler_processing,edit,sample_bank_files,sample_instruments}.rs`.

There is a declared 256 MiB per-bank ceiling and a process-shared 256 MiB aggregate bank ledger. Admission includes concurrent unpublished candidates, decoded SF2 zones, generated sources and retained generations. Identical prepared banks reuse their owner instead of taking a second lease. Distinct banks conservatively charge shared source capacity per zone. New project pools inherit the ledger before preparation. A reservation failure reports the request, current retained/preparing bytes and budget to native/UI callers; no oversized-bank exception exists.

PCM accounting uses `AudioBuffer` vector capacity, including unused capacity. Native bank decode reserves four decoded ceilings for transient sink growth and decoder PCM workspace before decoding, then shrinks the lease to retained PCM capacity. Unknown-length containers use one quarter of the ledger's remaining bytes as their decoded ceiling. This is deliberately conservative: an uncached source can be refused even when its final bank alone would fit. SF2 encoded bytes are separately admitted before an exact bounded file allocation; their lease stays alive while parsing/decoding. This is a bank PCM/admission policy, not a bound on all process memory, codec metadata or the general audio-clip cache.

Held and releasing voices retain their original bank index, PCM, mappings, filters, envelope, sample position and modulation phases. New notes use the newly selected bank. Fixed 257 owner slots cover 128 ordinary voices plus 128 fading choke tails with a spare owner. Handover swaps ownership; it does not destroy an Arc on the callback. Unused owners move through the existing control-side garbage ring; a full ring defers the sweep. Reset does not free owners. Multisampler effect state also survives bank handover.

### `fx-razer-chroma`

Implemented MusicLighting as a usable mixer effect, appended after the 67 saved effect kinds. Its editor exposes mode, device, level and RGB controls, plus real service status/refusal messages. The DSP is unity audio; control-side session realtime ticks read the existing track-meter path and actual musical clock. Reported effect-parameter/mix automation is resolved before publishing to a bounded worker channel. The audio callback performs no HTTP, locking or worker creation.

The dedicated worker uses the workspace's existing reqwest client and the public Chroma SDK REST interface: loopback POST initialise, PUT heartbeat every 1000 ms, PUT keyboard/mouse/mousepad/headset/keypad/chromalink static or none effects, DELETE uninitialise. Changes are sent at most every 50 ms; overlapping routes combine RGB maxima. Disabled/removed effects clear device output; shutdown closes the session. Failed service requests produce clear capability text and retry after two seconds. Requests have bounded timeouts and response bodies; external session URIs and redirects are rejected. No vendor SDK binary or new HTTP dependency.
