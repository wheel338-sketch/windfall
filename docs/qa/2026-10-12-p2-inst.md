## Changed files and common contract

- **D:** `crates/windfall-dsp/tests/dsp/instrument_deadlines.rs` — new public-API
  offline profiling module with one non-ignored test for each row.
- **M:** `crates/windfall-dsp/tests/dsp/main.rs` — explicitly registers D and
  reuses the target's existing global `realtime::CountingAllocator`.
- **P:** `crates/windfall-dsp/src/polysynth/pack_assets.rs` — adds a private,
  registered `#[cfg(test)]` cold-preparation test; production code is unchanged.
- This hand-off: `docs/qa/2026-10-12-p2-inst.md`.

Every D test runs at 48 kHz with exactly 128-frame stereo blocks. Each patch
gets three deterministic 750-block renders, exactly two seconds apiece, with
the declared maximum voice count checked before and after every block.
Finite percussion/PCM voices are retriggered every sixteen blocks so they
cannot expire and turn the profile into an idle benchmark. The patch must
produce nonzero energy, all samples must be finite, and absolute peak must
stay at or below the generous stress ceiling of 256.0. This ceiling allows
the intentionally dense sums; it is not a normal listening-level claim.

The existing TLS allocator counts allocation, zeroed allocation, reallocation
and deallocation. It must count zero through process, reset, note-on/steal,
note-off, repeated parameter/tempo publications, a real output-level transition,
stop and post-stop reset. Fixture construction, asset validation/cloning and
preparation occur separately on the control side. The test-only serialization
mutex is acquired before all preparation/timing and outside every callback guard.

The fastest **whole** two-second trial must take less than 0.75 times audio
duration; idle/tail frames are excluded from that ratio. Three matching PCM
fingerprints check deterministic reset and tolerate an OS scheduling interruption
in one timing trial. Logs report preparation time/allocated payload, render
time/ratio, slowest observed 128-frame process block, peak and declared tail.
Worst individual block time is reported, not asserted as a physical-device deadline.

After notes release, a separate guarded/profiled phase allows five seconds
for releases, renders the entire declared serial effects tail plus two blocks,
and demands zero remaining voices and exact silence. Release/tail wall time
has its own 0.75 ratio bound. Tail metadata must be bounded by sixty seconds.
All available chorus/echo/phaser/room stages are enabled at full mix in the
poly-family stress patches. Output gain is 0.25; amp/operator sustain is full,
attack is minimum and release is forty milliseconds where directly available.
Load dimensions, not a long silent attack, are maximized.

First construction/preparation, including authored maximum assets, must finish
within fifteen seconds and allocate no more than 64 MiB of new payload per
case. This is a generous control-thread ceiling, not an audio callback allowance.
P additionally calls `PackAssets::prepare()` directly, bypassing the shared
`OnceLock` cache, and requires the complete 7,010,304-byte bank in under fifteen
seconds. Every table and sample root/mip slab must be finite, bounded and populated.
It therefore measures actual cold preparation even if another test warmed `shared()`.

All production parameter/descriptor indices, persistence schemas, registries,
editors and callback implementations remain unchanged. No new dependency or
generated artifact is needed for these source changes. Parity files, bindings,
WASM artifacts and existing tests are untouched.

## Least certain spots

1. **Timing thresholds / dense operator cost:** D's `profile`, especially
   `sytrus_maximum_load_deadline`, `toxic_biohazard_maximum_load_deadline` and
   `gms_maximum_load_deadline` in table mode. These have not been measured in
   either the normal optimized-dev test profile or release. The existing
   `polysynth/operators.rs::matrix` repeatedly computes pitch/log/exp/sideband
   values per lane/operator/route, so the dense matrix may expose a real CPU
   shortfall. No speculative production optimization was made without a run.
2. **Full-load voice / PCM assertions:** every D case checks its count after
   every block. Pack multisample expiration, layered PCM lifetime, dense ring
   audibility, 256-frame scan interpolation and reset fingerprints are the
   most likely assertion failures. Read the printed parameter label and actual
   runtime behavior before changing any expectation.
3. **Release / tail assertions:** D allows five seconds to release then drains
   the declared tail, including the conservative maximum echo-line bound.
   Exact silence and the separate tail ratio remain unmeasured; the release
   allowance includes idle frames and is not part of the sustained-load ratio.
4. **Cold asset preparation:** P's fifteen-second ceiling, the populated-slab
   threshold and the exact 7,010,304-byte payload assertion are source-derived,
   not runtime measurements. The assertion deliberately forces review if the
   versioned bank layout changes.
5. **Compilation / formatting / Clippy:** D's typed variant construction,
   `AnyInstrument`/asset imports, fixed array/closure type inference, test macro
   registration and P's private child-module access were source-reviewed only.
   `DrumMode` is imported from `windfall_dsp::drums`, not the crate root. No
   compiler, formatter or lint validated the new code.
