## Row `wf-project-settings`

### What was wrong

When a bridged plugin asked to be restarted, the desktop's capture
(`capture_pending` / `capture_at_deadline`) called `Record::readmit`, and
the helper's `Native::readmit` deactivated the plugin at once. The helper
never faded out or reported its notes' ramps; the departure that
`Runtime::bridge_audio` asked for afterwards found a deactivated helper and
an empty carry, and the replacement started each replayed note at its target.

### What changed

- `apps/desktop/src-tauri/src/plugins/bridge.rs`
  - `Record::readmit` now asks the unit to leave first
    (`departure.leave(150 ms)`): the helper fades its output out over 5 ms,
    holds every ramp and reports it with each block, and the unit writes the
    carry, all before `Message::Readmit` deactivates the plugin. A failed
    re-admission withdraws the departure (`stay`), so a helper that still has
    its plugin fades back in.
  - `Departure` gained `held`: set by a re-admission, it keeps the two-second
    expiry in `Audio::process_sidechain` from withdrawing the request while
    the document prepares the replacement (the plugin is gone; playing on is
    not possible, and withdrawing would clear the carry). `stay` clears it.
  - `Departure::leave` returns at once when the request already stands and
    the unit has faded out, so `bridge_audio`'s departure (runtime.rs, the
    lines the audit cites) reuses the carry written before the re-admission
    instead of asking a deactivated helper to fade.
- `apps/desktop/src-tauri/src/plugins/runtime.rs`: the comment at the
  `bridge_audio` departure says the above; `selected_bridge` (test-only,
  `pub(super)`) hands a test the departure and the re-admission flag of the
  helper playing a target.
- Bridge protocol: unchanged. No message, word or slot field was added (the
  fade, the report and the carry are the version-11 words), so `VERSION`
  stays 11 and earlier helpers are refused as before.
- Fixtures that change what they offer per note **on their own, while
  running**, and ask for a restart:
  - VST3 class 29, "VST3 Restarting Expression Switch"
    (`test-plugins/src/vst3.rs`, appended; `CLASSES` 29 to 30). Like class 28
    it offers pan and volume per note; parameters 8 and 9 withhold pan and
    volume. Its controller follows the two parameters itself when the host
    passes the processed values to it (`setParamNormalized`), and while active
    announces the change with `kNoteExpressionChanged`; its processor keeps
    what it offered at activation (`latched_withheld`, set in `setActive`).
    Class 28's behaviour is unchanged. Count assertions moved 29 to 30 in
    `tests/vst3_scan.rs` and `tests/vst3_bundle_macos.rs`;
    `ownership_tests::fixtures` treats 29 as an instrument.
  - CLAP "Test Switching Sine", `org.windfall.test.switching-sine`
    (`test-plugins/src/{lib,plugin,ext}.rs`, appended to the spec list): the
    sine with a stepped "Note dialect" parameter (id 2, 0 CLAP notes, 1 MIDI
    only) and state that saves it. It plays the dialect it had at activation
    and calls `host->request_restart` from `process` when the parameter
    changes while active (never while inactive, so a replacement loaded with
    the new value does not ask again).
- Capability panel (`features/plugins/note-capabilities-view.tsx`) and its
  catalog entry, English and Spanish (`lib/i18n/inspector-messages.ts`): "…and
  follows the most recent note that sounds; notes that overlap share it." /
  "…y sigue a la nota más reciente que suena; las notas que se solapan la
  comparten." The old sentence's two entries were replaced, not left behind.
- Audit's minor item: a UI test edits the transport bar's time-signature

### Least certain spots (row one)

- **The VST3 self-announce path inside the helper.** Class 29 relies on the
  VST3 host's owner-thread `idle` calling `setParamNormalized` on the
  controller after the processor took the point (it does in
  `vst3/instance.rs::idle` when active), and on the restart flag raised there
  being turned into `RestartRequested` in the same `idle` (following is off
  in the helper). If the helper's `idle` passes no active processor, the
  plugin never asks and the new test fails with "the plugin never asked to be
  restarted" after 30 s. The host-level test isolates this.
- **Timing of the app-path test.** It waits (wall clock) for the owner's
  publication and the re-admission flag, pauses audio only until the
  departure is requested, then needs the fade to finish within `leave`'s
  150 ms while it plays 64-frame blocks with 2 ms sleeps, as `migrate` does.
  A slow machine could make `leave` give up before the fade; the test then
  fails on "the output faded out before the plugin was given back".
- **Live equal to offline**: the live run is compared with `migrate` run
  offline on the same before/after bindings. That holds if the old helper's
  audio is unchanged by the switch (the fixtures latch their offer, so it
  should be) and if a warm helper and a fresh one align the same way from the
  note on.
- `capture_pending` is handed the first matching capture request seen; if
  the owner had published one before the restart (an unrelated native
  change), it is that one, which `capture_pending` accepts (its serial is not
  above `dirty_serial`).
- `Departure::leave`'s new early return and the `held` flag are small but sit
  on the path of the existing bridged tests.

### What each audit item should now satisfy

1. Each named field is mapped with a stated scaling and a fixture test:
   imported value, the audible effect against a reference worked out in the
   test (the phaser's allpass-and-feedback response at the imported color;
   the synced rate equals the fitted rate at the import tempo; wet only has
   no dry and twice the even mix's wet; the stereo shaper's side is the input
   shifted by the stated samples; the panomatic's pan and gain law), and save
   and reopen with the original state kept.
2. The general check: the pinned list now requires, per device, the stand-in
   controls that no decoded field sets to equal a reviewed line, computed
   from the stand-in's actual descriptors, and each omitted entry carries a
   reason. Doing this exposed BassDrum `peak`, Vocoder `num_bands`, Pitcher
   `key_on`, Pitch Shifter `formant_correction`, and in the effects read by
   number Reeverb pre-delay and modulation, Delay 2 stereo offset and
   feedback cut, Delay cutoff and own tempo; all are mapped and tested. The
   ones kept omitted next to a similarly named control are listed with their
   reasons in `coverage.md`.
3. SimSynth's switches and the 3x Osc's stereo detune and osc-3 AM are no
   longer part of an approximated line: the stand-ins have no matching
   control, so they are filed as omitted, listed per device and pinned; so
   are the channel envelope, LFO, arpeggiator, note-echo and time-stretch
   fields. The pinned list is complete for native and channel fields.
4. The import review test renders a report from the real converter (the
   simulator) and checks every shown category's counts against it and the
   per-device "Omitted controls" section.
5. `docs/flp/coverage.md` lists the same 269 families on 43 devices.

Note for reading the review: a category's exact / approximate / placeholder /
omitted counts tally channels, effects and the like; an omitted field is a
dropped line of its category and an entry of "Omitted controls" (as in round
seven). The tests check the lines, not those tallies.

### Least certain spots (row two)

- **`every_omitted_field_was_checked_against_the_controls_of_its_stand_in`**:
  the `UNSET` lines were worked out by hand from the descriptor macros. A
  family I misread makes the test fail with both sets printed; that is a
  table fix, not a code fix. Likeliest: the Delay Bank units, the Waveshaper
  curve points, the Slice Deck slices.
- **Audible references that depend on DSP details I read but could not run**:
  the Vintage Phaser response (assumes the left sweep sits at the middle with
  the rate at 0 and the color low-pass is in the feedback exactly as read);
  the BassDrum cycle count (assumes the kick body is the only signal after
  5 ms with click 0 and no sample); the Pitcher correction (assumes speed 0
  snaps and the corrected tone dominates within 1.5 s); the Reverb shift
  (assumes the network is time-invariant with modulation 0); the Delay second
  echo (assumes the feedback filters are the two SVFs read, at Q 0.707, and
  that the first echo is unfiltered); the Vocoder (assumes its synth carrier
  makes sound from the modulator alone; that check is only "heard and not the
  16-band sound").
- **Rules that are Windfall's reading of an unstated range**, disclosed in
  the report and `coverage.md`: Pitch Shifter `wet` 0..10000, Panomatic
  `lfo_target` value order, Stereo Shaper side, Reeverb 2 pre-delay fit.
- **The UI test** needs the rebuilt simulator, and assumes an FL 9 stream with
  a SimSynth channel followed by the master's slot (the order the Rust tests'
  helpers use) converts as both of them do separately.
- Clippy: index loops and small `vec!`s were avoided in the new tests; the
  `UNSET`/`EXPECTED` tables use long string literals (fine for rustfmt).
